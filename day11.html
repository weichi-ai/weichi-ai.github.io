01

WHAT IS API

什么是 API？

「API 就是 Application Programming Interface 的缩写，应用程序接口，是"软件之间沟通的桥梁"。」

如果一个软件想使用另一个软件的能力，不需要知道里面怎么做，只需要通过 API 提出请求，然后拿到结果。

这有点像餐厅点餐

想象你去一家餐厅，你不会直接跑进厨房喊"厨师，给我炒个蛋炒饭！"因为：你不知道厨房怎么操作、不知道食材在哪里、可能把厨房搞乱。所以你指着菜单告诉服务员："我要一份蛋炒饭。"服务员把你的需求告诉厨房，厨房制作，把结果端回来。

餐厅软件世界
顾客你的程序
菜单API
厨房服务器/系统

02

WHY API

为什么要有 API？

如果没有 API 会怎样？

假设你开发一个天气 App，想显示"上海今天多少度？"怎么办？自己买气象卫星、建气象站、收集全球天气数据、开发天气预测模型？成本巨大也不太现实。

但是有 API：天气公司已经做好——天气系统 → 天气 API → 你的 App。你的 App 只需要问：请告诉我上海天气。

{ "city": "上海", "temperature": 32, "weather": "晴" }

你显示：☀️ 上海 32℃ 晴。

API 的核心价值

1. 复用能力——别人已经造好的轮子，你直接使用。比如：支付，不用自己造银行系统，调用支付宝 API、微信支付 API；地图，不用自己测绘，调用高德地图 API；AI，不用自己训练大模型，调用 OpenAI API、Claude API、豆包 API。

2. 隔离复杂性——比如 ChatGPT：你看到的是"输入：帮我写一篇文章；输出：文章内容"。背后其实是你的程序 → API → 大模型服务器 → GPU 计算 → 返回结果。你不用懂 Transformer、GPU 并行、模型参数，只需要调用 API。

HOW TO USE

如何使用 API？

你需要拿到API 三件套：调用地址、访问密钥、调用示例。有的 API 会提供测试和生产两套信息；也有些测试和生产是同一套，有少量测试用量，超了就停止服务或开启计费。

在正式接入 API 前，推荐用 Postman 先"验货"再接入代码——因为如果在实际写代码前就先把 API 调通，会对 AI 写代码增加很大的确定性。接下来以调用火山引擎的生图模型为例，展开说说 Postman 的用法：

API 正常，可以接入软件了

💡 说明 API 正常，可以把 API 接到你的软件中了，以传统或 AI 的方式。

「人或 AI 在实际写代码前，就先把 API 调通，会给 AI 写代码增加很大的确定性，节省不必要的麻烦。」

当然这个过程也完全可以让 AI 帮你去做测试，不需要 Postman。但如果你自己会用 Postman，API 的验证会更灵活、也能节省一点点 token，排查问题时可能也会更高效。
