小结与提醒

有人写脚本一秒注册几十个号，每个号用完免费额度就扔掉——你花钱买的 AI 接口额度，就这样被薅走了。

今天第 12 天，这几天的学习难度不断加大，今天挑一个轻松点的来聊聊——如何防止被薅羊毛？答案是人机验证。

01

PART

为什么你的产品需要人机验证？

WHY

你可能觉得：我的产品还很小，谁会来薅？但现实是：互联网上"薅羊毛"是自动化的——有些人写通用脚本专门扫描新产品，发现免费额度就自动注册。产品"小"不代表安全，恰恰相反，小产品往往更容易被薅，因为你没做任何防护。

更关键的是：你的 AI 接口是花钱的——每次调用都在烧钱。真实用户一天用三五次，脚本一分钟就能调用几百次。

没有人机验证的产品就像门口没有锁的店——不是一定会有人偷东西，但你把门开着，迟早会出事。只要产品有注册功能，就应该加人机验证。

02

PART

什么是人机验证？

WHAT

你其实每天都在遇到，只是没注意：登录网站时出现"请证明你是真人"/"I'm not a robot"的小方块，有时候点一下勾，有时候什么都不用做就通过了；有时让你从图片里选出红绿灯。

这个东西叫人机验证，英文叫CAPTCHA。本质很简单：在用户和你的产品之间加一道"安检"。对真人用户几乎没有感觉，对机器人是一道过不去的坎。

打个比方：你开了一家餐厅，门口排了很长的队，突然发现队伍里混进来一堆机器人——它们不是来吃饭的，是来免费拿餐巾纸的。怎么办？在门口放一个保安，让每个人证明自己是真人。人机验证就是你产品门口的保安。

市面上做人机验证的服务不少，最有名的是 Google 的 reCAPTCHA（点红绿灯、选自行车那个）。但我们推荐Cloudflare Turnstile：

① 免费：完全免费，没有请求量限制（reCAPTCHA 免费版有调用量限制）

② 用户体验好：大多数情况下用户什么都不用做——Turnstile 在后台分析浏览器行为、鼠标轨迹判断是否真人，只有"拿不准"时才让用户点一下勾

③ 不收集隐私数据：Cloudflare 明确承诺不会用人机验证数据做广告或用户追踪（Google 的商业模式就是数据）

④ 接入简单：前端加一个组件，后端加一个验证接口

03

PART

Turnstile 的三种模式

MODES

模式行为适合场景
Managed（托管）★推荐Cloudflare 自动判断：明显真人直接放行；有点可疑显示小方块点一下勾；大概率机器人验证失败。最多点勾，不会选红绿灯绝大多数产品，用这个就够了
Non-Interactive（非交互）页面显示带加载动画的小组件，用户完全不需要操作，后台自动完成希望有可见"验证中"提示但不想让用户操作（如支付确认页）
Invisible（隐身）完全看不见，无组件无动画，后台静默完成追求极致视觉简洁；注意：Cloudflare 要求你在隐私政策里说明使用了 Turnstile

我的建议：直接用 Managed，不用纠结——低风险用户自动放行，高风险用户才需要互动，是最好的平衡。

04

PART

五步给你的项目加上人机验证

HANDS-ON

STEP 01

注册 Cloudflare，创建 Turnstile 组件

注册 Cloudflare 账号 → 左侧菜单找到 Turnstile → 点 Add Widget → 填组件名称和域名（本地测试可以填 localhost，也可以先用官方测试 Key 跑通流程）→ 组件模式选 Managed → 创建。创建后拿到两个 Key：SiteKey（放前端，公开的）和 SecretKey（放后端，绝不能公开）。

STEP 02

把 Key 配到环境变量里

打开项目根目录 .env.local（没有就创建），加上两行：

NEXT_PUBLIC_TURNSTILE_SITE_KEY=你的SiteKey

TURNSTILE_SECRET_KEY=你的SecretKey

注意：SiteKey 前面有NEXT_PUBLIC_ 前缀（Next.js 里带这个前缀的变量才能在前端使用——SiteKey 本身要展示，需要这个前缀）；SecretKey 没有前缀（只在服务端使用，绝不暴露给前端）。或者让 AI 帮你加也行。

STEP 03

安装前端组件

运行 npm install @marsidev/react-turnstile——一个封装好的 React 组件库，方便在 Next.js 里使用 Turnstile。

npm install @marsidev/react-turnstile

STEP 04

在注册页面加上人机验证组件（前端）

AI 会自动加上组件，你可以问 AI：加在哪个文件、从哪行代码开始，并让它写上中文注释——每行代码什么作用都标注上。

STEP 05

后端验证——最关键的一步！

做完第四步其实才走了一半。前端的验证是可以被绕过的——懂技术的人可以跳过注册或登录页面，用代码直接往后端接口发请求，根本不经过 Turnstile 验证。如果后端不检查 token，人机验证就形同虚设（就像仓库放了门卫，但后门敞开着）。

直接问 AI：有没有检查 Token？代码在哪里？去证实一下。

的确有做 Token 检查：

import { NextResponse } from "next/server";

export async function POST(request: Request) {

const { token } = (await request.json()) as { token?: string };

const secret = process.env.TURNSTILE_SECRET_KEY;

if (!secret) {

return NextResponse.json({ success: false, error: "Turnstile secret is not configured" }, { status: 503 });

}

if (!token) {

return NextResponse.json({ success: false, error: "Missing verification token" }, { status: 400 });

}

const form = new FormData();

form.append("secret", secret);

form.append("response", token);

const response = await fetch("https://challenges.cloudflare.com/turnstile/v0/siteverify", {

method: "POST",

body: form,

});

const result = (await response.json()) as { success?: boolean };

return NextResponse.json(result, { status: result.success ? 200 : 403 });

}

LAST

⚠️ 重要提醒：SecretKey 绝不能公开——如果已经泄露（比如贴在了文档/截图里），去 Cloudflare 后台重新生成一个，旧的作废。

① 只要产品有注册功能或免费资源，就一定要加人机验证

② 前端验证可被绕过，后端必须也验证（检查 token）

③ 推荐 Cloudflare Turnstile Managed 模式：免费、体验好、不收集隐私

④ 遇到报错别慌：把错误发给 AI，按它的指引定位修复（这次就是 localhost vs 127.0.0.1 的小坑）
